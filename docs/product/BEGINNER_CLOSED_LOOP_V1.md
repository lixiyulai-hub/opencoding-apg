# 小白闭环（离线可验收版）

OpenCoding 的主验收对象是不会写代码、刚开始用 AI 编程的人。用户只需用大白话说目标，系统按下面顺序工作：

1. 保存目标，按依赖顺序追问使用者、业务结果、平台和能力需求。
2. 判断客户端平台、技术栈，以及服务器、数据库、API、登录、支付、通知、后台和存储是否需要；`unknown` 保持未解决。
3. 生成项目专属 `AGENTS.md`、`memory.md`、`PRG.md`、`plan.md`，以及按能力选择的产品、界面、架构、数据、接口、权限和边界文档。
4. 用同一份 Recommendation/TaskPlan 生成依赖和波次，先展示差异，再绑定会话版本、文件范围、哈希和有效期。
5. 用户确认后写入本地文档事务，保留 receipt、前后哈希和回滚入口。
6. 使用 `--run-plan SESSION_ID` 启动离线产品任务账本。每个已生成文档任务会记录测试类型、文件字节与 SHA256、时间和回滚说明。
7. 支付、通知、部署等外部能力在任务账本中停在人审 Gate；`--resume-plan RUN_ID --confirm-gates` 只记录确认并继续离线设计，不连接服务商。
8. 真正的项目代码实现/测试会明确停在 `blocked_capability`，因为当前包没有项目专属执行器；不会把缺少源码冒充成失败修复或成功实现。

账本写在项目 `.opencoding/product_runs/` 下，可读取、接续和记录回滚。回滚账本不会删除用户文档；文档撤销仍使用预览产生的 document transaction 回滚。

## 能力状态

已在 Linux 离线验证：中文输入与追问、平台和能力判断、同源方案、文档生成、任务依赖/波次、预览确认、版本漂移拒绝、事务回滚、逐任务证据账本、外部能力人工 Gate、账本接续和停止记录。

仍需人工环境或额外资产：真实项目代码执行器、真实浏览器点击、Windows、Docker、Rust/cargo、frontend、真实 provider、登录/支付/通知/部署。它们保持明确阻塞，不由离线模拟替代。

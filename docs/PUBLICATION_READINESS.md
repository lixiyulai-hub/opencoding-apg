# Publication readiness（公开发布准备检查）

这里的 Publication 指“把 APG 内容放到公开渠道让别人看到”，不是部署到
Codex Host。部署已经完成并不等于可以公开发布。

## 自动判断结果

- `ready`：资料齐全，可以给负责人做一次最终确认；系统仍不会发布。
- `needs-owner-gate`：缺少目标公开渠道、内容范围、来源摘要、撤回方案或观察窗口，
  或者确实需要负责人确认；系统停在预览状态。
- `blocked`：资料不安全、范围不清或涉及不可逆/敏感条件；系统停止。

## 自动检查的内容（小白版）

1. **发到哪里**：例如公开网页、文档站或代码仓库；本地预览可先写成
   `project-local-preview`。
2. **发什么**：只允许明确写出的内容范围，不能把整个工作区顺手公开。
3. **依据哪一版**：绑定已经验证过的制品校验值和来源摘要。
4. **能否撤回**：写明删除/下架公开副本后如何记录结果。
5. **观察多久**：发布后由负责人确认的观察窗口。
6. **上下文是否安全**：是否联网、使用密钥、花钱、真实数据、改 Git、启动运行时。

评估器只读取并重算这些资料，返回中文说明，`execution_performed` 永远为 `false`。
它不会联网、不会调用 provider、不会改 Git、不会部署、不会公开发布，也不会推进
Pilot 或 Release。

## 当前项目结论

当前 APG 已在本机 Codex Host 生效，Deployment 已接受；Publication 仍是下一项独立
人工 Gate。此次工作只准备本地设计预览和自动 readiness 评估，不创建公开页面、不上传
文件、不发送网络请求。负责人以后只需回答“公开发到哪里、公开哪些内容、确认发布”这
类大白话问题，系统会自动生成技术字段和证据绑定。

## 后续边界

Publication 通过后才可进入 Pilot；Pilot 通过后才可进入 Release。每一段都要有独立的
ChangeRecord、证据、回滚/撤回方案和接受结果，不能用部署证据代替公开发布证据。

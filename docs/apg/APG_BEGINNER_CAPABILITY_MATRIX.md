# APG 初心者能力需求矩阵

这份矩阵说明 APG 如何从一句中文目标主动判断项目需要什么，不要求小白先懂技术。

| 能力 | 判断依据 | 系统给出的方案 | 是否可能触发 Gate |
| --- | --- | --- | --- |
| 服务器 | 联网、多人、在线同步 | 先做轻量后端 API 的离线契约 | 是 |
| 数据库 | 登录、记录、订单、长期保存 | 先按关系型数据建模 | 是 |
| API | 客户端、第三方服务或 AI 交换数据 | 先定义接口和模拟响应 | 是 |
| 登录与权限 | 用户、家长、管理员、账号 | 先做假登录和权限矩阵 | 否（真实身份服务另行确认） |
| 支付 | 付款、订阅、订单、退款 | 先做支付流程和订单状态模拟 | 是 |
| 消息通知 | 提醒、推送、短信、邮件 | 先做通知事件和失败重试模拟 | 是 |
| 后台管理 | 审核、运营、报表、管理员 | 先做最小后台角色和审计列表 | 否（真实上线另行确认） |
| 文件存储 | 图片、视频、附件、上传 | 先做本地假实现，再规划对象存储 | 否（真实存储另行确认） |

输出字段固定包含：`capability`、`need`、`status`、`reason`、`source`、`recommendation`、`risk`、`gate_required`、`evidence`、`rollback`。

当前实现只生成内存预览，不连接服务器、数据库、API、支付、通知或后台服务。

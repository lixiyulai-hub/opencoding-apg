# APG Git 检查点策略（中文初心者）

1. 成功节点 + 证据完整 + 测试通过 + scope 干净：建议建立一个 Git 检查点。
2. 同一节点已经建议过：抑制重复建议，继续使用原 checkpoint_id。
3. 失败、缺证据、范围漂移或无法判断：进入 FREEZE，退回最近已验证检查点。
4. `recommendation` 只是自动化提示，不是审批队列。
5. 所有离线结果都标记 `PREVIEW_ONLY`，不执行任何 Git 动作。

## 用户看到的中文提示

- “这个小目标已经验证通过，我建议现在保存一个回退点。”
- “出现问题时，先退回最近一次已验证的检查点，再继续。”
- “当前证据还不完整，系统先冻结，不创建新的检查点。”

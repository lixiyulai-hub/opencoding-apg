# APG 自动化 PRG 策略（APG-only）

## 目的

APG 面向不懂编程的用户。用户只需说出想法，APG 自动完成计划、任务拆分、循环推进、验证、报告和下一轮安排。用户不需要阅读专业术语，也不需要反复点击“批准”。

## 默认规则：AUTO

下列动作自动进行：

- 把自然语言整理成结构化计划；
- 选择安全、低成本、可回滚的默认方案；
- 生成任务、依赖、波次、Gate、证据和回滚入口；
- 运行离线检查、重放、报告和 requeue；
- 遇到普通歧义时采用可解释的保守默认值，并把选择记录到证据。

`RECOMMEND` 只表示“系统自动采用了一个默认方案并说明原因”，不是人工审批点。

## 唯一必要 Gate

只有可能造成外部影响的事项才暂停一次，并把同一事务的原因合并为一个 Gate：

- 密钥、密码、令牌或身份材料；
- 金钱、付费、配额或预算；
- 网络、Provider、第三方 API；
- 部署目标、上线环境或运行时启动；
- 真实/生产数据；
- Git 推送、公开发布；
- 删除、发送或其他不可逆外部动作。

系统不会把多个小问题拆成多个审批，也不会把小白用户变成技术审核员。

## 自动冻结

缺少证据、首次失败、范围漂移或结果不确定时，loop harness 自动进入 `FREEZE`，保留证据并生成机器可恢复的 `resume_condition`。用户只看到“正在修复/等待必要信息”的简短说明，不负责诊断内部错误。

## 边界

本策略只描述 APG 自身的自动化验收和 PRG 编排。它不代表任何下游产品、Host、Runtime、部署或发布已经执行。
